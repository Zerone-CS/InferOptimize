# 限制形态、竞争假设与下一动作

需要：可信 `N_Y/T`、输出/成功/时延分布、负载与配置身份、ledger 和原始引用；同时查看已反驳假设、失败实验及固定 KB 身份。历史 profiling 未匹配当前运行时只作候选线索。

## 执行

按 [因子诊断](factor_diagnosis.md) 检查账本，按 [归因方法](attribution.md) 设计鉴别；需要扩展解释时查 [假设树](root_cause_tree.md)。

1. 检查目标、总账和比较边界。计量无效先提出修复；探索线索可保留，不能据此判收益。未知量不当零，估计不当精确实测。
2. 描述供给、吞吐平台、实际参与、图回退、KV 或 rank 差异等限制形态。五因子是符合条件时的记账恒等式；最小因子、最大时间占比、未饱和/已饱和均不能唯一定位根因。
3. 对观察列竞争假设：适用范围、机制链、支持证据、替代解释和缺失项。区分“路径被允许”“实际走过”“影响完成时间”“改变后有收益”；关键路径需依赖与资源串行证据，通信可能含等待，空白可能为漏采。
4. 写每个解释对因子及中间信号的预测和反证条件。按辨别力、收益空间、成本、风险、可逆性及依赖选择重算、定向补采、语义标记或受控干预。
5. 用 target_factor/mechanism 表述 [知识查询](../../knowledge/references/workflow.md) 意图，再转换为 CLI 真正支持的字段/全文查询。保存固定快照、命中与现场源码核验；推荐值不证明瓶颈，缺卡不排除优化空间。源码足够时不强制全库重建；建设建议交协调者安排，不由查询自动触发。
6. 按证据考虑参数、图/shape、算子/融合/布局、调度/KV、通信/并行/负载分配和代码路径；不受参数库范围限制，也不要求逐路实验。预测正负因子及质量/SLO/资源变化，按净 `N_Y/T` 判读。

## 候选与返回

每张候选卡保留以下内容，字段见 [诊断记录](records.md)：

| 内容 | 要回答的问题 |
|---|---|
| observation + scope | 哪个 run/窗口/版本/负载观察到什么 |
| target_factor + mechanism + alternatives | 要改变哪个量，机制与竞争解释是什么 |
| predicted_outcome + mechanism_signal | 最终指标与中间信号预计怎样变化，包含代价 |
| falsification + guardrails | 什么结果反驳解释，如何保护质量/SLO/资源 |
| next_action + cost/dependencies | 具体输入、成本、停止/回退条件及结果分支 |

交付限制形态、假设卡、证据/KB 引用、候选排序和下一动作。限制与可执行鉴别清晰即可 `completed`；关键解释仍不能区分时返回 `needs_evidence` 与最小鉴别方案。
效果与机制分别判定：样本不足不是“已证明无效”，有收益而归因未明可记 unresolved。保留旧假设和排除项，不把本轮结束写成全局最优。
