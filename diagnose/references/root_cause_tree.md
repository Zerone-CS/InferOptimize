# 吞吐假设树

这是生成和区分假设的索引，不是看到一个阈值就自动判根因的规则。
先用 [因子驱动诊断](factor_diagnosis.md) 的观测表定位有关分支，再在此查竞争解释与鉴别方法；
分支没有观测时标记缺口，不能凭未出现异常日志认定它正常。
先读 evaluate 的 [测量契约](../../evaluate/references/measurement_contract.md)；同一表现可落入多个分支，候选以证据、约束和成本排序。
比例阈值、图形状公式和推荐参数值均需本环境验证，不提供通用的 40%/25%/95% 门槛。

## A. 测量或供给尚未解释

| 观察 | 候选解释 | 最小鉴别证据 | 不充分证据 |
|---|---|---|---|
| token/s 随负载不变 | 到达供给限制、服务容量限制、客户端瓶颈 | 计划/实际发送、终止、队列、负载扫描 | 只比较目标 req/s 与 token/s |
| 多次结果波动 | 热态/JIT、共租、请求构成、随机性、工具错误 | 全部重复样本与环境/长度/计数对账 | load 高或一次离群就断言污染 |
| 上报吞吐特别稳定 | 固定输出实际相同，或脚本使用配额估算 | 实际 usage/生成 ID 与汇总算法 | 配额算术吻合即认定实际输出相同 |
| TTFT/ITL 异常低 | 首事件空载荷、起点记录过晚、分块方式 | 客户端逐事件与计时位置 | 只读 summary 字段名称 |
| 参数改了却无效果 | 生效覆盖、负载不敏感、假设错误、噪声 | 请求值/解析值/实际路径，当前重复对照 | CLI 接受或启动成功 |

供给受限时仍可比较固定负载时延和 goodput；容量问题需另设受约束扫描。
不把“未饱和”直接路由为 tokens/step 问题。

## B. 每轮有效产出及成功保留

| 观察 | 候选解释 | 鉴别方式 | 代价与交互 |
|---|---|---|---|
| 实际参与序列少，队列有工作 | KV、序列/token 预算、准入策略、prefill 排布 | 调度未准入原因、实际 B_k、KV 分配/抢占 | 放大 batch 也可能增加轮间隔和尾时延 |
| KV 使用高且等待/重算增加 | 活跃上下文、缓存布局、预算/工作区争用 | KV 分配与失败原因、上下文长度、重算 | 高使用率单独不证明容量瓶颈 |
| 投机接受输出少或尾位置弱 | 草稿匹配、长度分布、调度/停止规则 | N_G/N_C、位置接受与完整轮代价 | 减少草稿可能同时降低产出与耗时 |
| 中间 prefill 步产出零 | 正常输入处理、chunk 预算、prefill/decode 竞争 | 请求阶段与工作量/时延，不只数输出 | 中间零输出不自动算浪费 |
| 产出未成为成功输出 | 停止裁剪、正常 EOS、超时/取消/错误 | 唯一输出位置、停止原因、最终状态 | 正常结束不可通过强行延长输出来“优化” |

候选包括调度预算、KV/内存布局、投机策略、前缀复用等，先验证版本和模型支持。
不得用客户端并发或 padded shape 代替 B_k；不要将配置上限当作实际参与量。

## C. 完成间隔及完整服务时间

| 观察 | 候选解释 | 鉴别方式 | 不能直接推出 |
|---|---|---|---|
| 通信事件覆盖大 | 数据交换、同步等慢 rank、拓扑、集合通信算法 | 多 rank 关联、消息/拓扑、重叠、等待来源 | 通信占比就是可回收比例 |
| 时间线空白多 | host 下发、供给、同步、I/O、未采到事件 | host/device 关联、队列与阶段范围 | Free=host overhead |
| 小 kernel/API 多 | eager 路径、图覆盖、算子拆分、动态条件 | 实际图键/命中、API 关联、执行形状 | 小算子多就必须扩图 |
| 图捕获存在但性能差 | 部分 shape 回退、padding 浪费、重编译、其他瓶颈 | 逐步实际 shape/图键及路径选择 | `(spec+1)×客户端并发` 精确判断覆盖 |
| 计算活动持续长 | 运算量、访存、占用率、依赖、融合机会 | shape/dtype、匹配 PMU、算子实现与对照 | Computing 高必然算力受限 |
| rank 时间差大 | MoE 专家不均、通信拓扑、主机/设备争用 | rank 工作量、路由统计、依赖时间线 | 慢 rank 的通信 kernel 自身效率差 |

可行动作可能涉及图范围、融合、异步调度、并行/通信策略、亲和性或算子实现。
每项都要检查当前版本约束；依赖 EP/SP/图/投机的组合按依赖束实验登记。
若模型输出数变化，应先完成测量对账，再解释时间减少的来源。

## D. 配置、质量和运行可用性

| 观察 | 候选解释 | 鉴别方式 |
|---|---|---|
| 低精度参数被覆盖 | 模型支持条件、平台兼容路径、分组限制 | 实际源码 guard、解析后配置与执行路径 |
| 配置启动失败 | 配置不支持、资源不足、安装混用、通信/运行时问题 | 最早相关异常、目标环境版本、资源归属 |
| 吞吐提高但输出变化 | 数值误差、采样变化、停止/长度变化、实现错误 | 固定参考、任务质量基准、实际长度与参数 |
| 吞吐提高但尾时延恶化 | 排队、batch 变化、调度倾向、服务容量边界 | 同负载逐请求分布与预定 SLO |

启动失败只证明该配置在当前条件下未运行成功，不自动否定整个优化方向。
旧的硬件/模型/版本案例仅作为检索线索；有效的候选仍需当前安装源码和实验确认。

## 候选优先级和退出

优先选择：目标约束关联明确、区分能力强、成本较低且可回退的实验。
每次采纳后检查是否出现新的限制，不把旧瓶颈比例固定用于所有后续配置。
当诊断范围已完成或预算达到停止条件时返回未验证项；是否结束整个 campaign 由协调者结合目标和其他可行方向决定。
报告应区分“本轮未找到更好配置”与“证明系统最优”。
