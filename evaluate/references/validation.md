# 吞吐优化验证

需要：主入口固定的实验契约、baseline/candidate 完整身份、计划与实际变更集、原始运行或执行方案。机制验证另需实验前预测与诊断模块提供的 ledger、原始引擎/profiling 证据及其解释。
本能力可以单独核验已有数据，返回判定建议；不调整成功标准，不修改服务或当前基线。

## 执行

1. 按 [计量定义](measurement_contract.md) 核对完整窗口、实测有效输出、终态与客户端策略。缺失、中断和真实失败分别记录；原始运行不可覆盖或补写成功。
2. 核对环境/配置/源码及实际生效证据。全部场景各自绑定同一个 baseline 部署和同一个 candidate 部署，保护场景不能沿用原配置；每个重复必须是独立运行。
3. 按委托范围复核已有数据、准备矩阵/命令/判据，或运行全场景配对/交错重复；服务执行遵循 [任务交接契约](../../references/suite_contract.md)。预热、预检与诊断分开；正式收益不采用重型 profiling 数据。
4. 按 [工具用法](tool_usage.md) 调用元数据准备、采集、校验与比较工具；已保存输出可用 `compare_outputs.py` 抽检。公开字段见 [工具数据接口](tool_contract.md)。工具不证明声明真实、质量充分或机制成立；有限批次不证明稳态容量，chunk 间隔不是逐 token ITL。
5. 独立检查约定质量与全部 SLO，核对输出长度、停止规则及失败变化。样本 exact-match 不等于普遍质量等价，均值改善不能抵消尾时延/错误率或其他场景超限。
6. 消费 diagnose 的 [公开观测记录](../../diagnose/references/records.md)，依计量定义核对因子变化与机制预测，包括窗口、唯一归属、覆盖、零分母及独立对账；不混算短 trace 与整批输出，不凭收益自动认定机制成立。证据不足时返回缺口，不隐式启动诊断。
7. 保存全部重复、效应与不确定性，按事前最小收益和逐项保护条件判读。有效计量、实际质量/配置证据、全部主指标与保护条件满足契约才建议采纳；超限返回回退建议，证据不足 defer，不能写成“证明无效”。胜出候选按计划独立确认，效果与机制分别报告。

## 重复、噪声与建议

先重复当前场景基线，再以配对/交错顺序比较候选，记录每次环境和运行顺序。重复数随波动与预期收益调整；三次中位数只是描述统计，不是通过门槛。保留全部样本、效应估计和不确定性，区间估计注明方法与假设。异常样本只凭事先规则或独立污染证据标记，不按结果好坏选择性删除。

单遍 +3.8% 只能报告该次观察，不能与旧环境的“噪声 ±2%”拼成采纳结论。回归矩阵逐项检查约定的 p50/p95/p99 等指标；均值改善不能覆盖受保护 p99 恶化。不确定范围、最小有意义收益、业务容忍退化分别记录。

判定保留五个维度：数据有效性、质量/SLO、性能效果、机制、决策建议。性能效果不确定时可建议预算内补测；预算用尽仍缺证据则建议 defer。性能改善但机制信号不符预测时，机制标 unresolved/contradicted，不补凑解释。adopt/revert/defer 只是评估建议，主入口拥有最终决策和状态写入权。

## 正确性比较

参考输出只读保存并计算 hash；候选输出使用新目录。执行前核对真实 CLI 的参数方向，优先具名参数；仅有位置参数时保存 argv 与明确映射。比较器不得写回参考；重建参考需要新 reference_id 和原因。

保存完整 stdout/stderr 和原始比较器退出码；经 `tail`/`tee` 展示时不使用显示命令状态替代。离线测试覆盖“输出不同”“参考缺失”等失败路径。抽检、任务质量基准、精度容忍度分别报告，无法完成约定质量验证时不写“无损”。

## 完成与产物

按 [评估记录](records.md) 交付原始运行、校验报告、质量/SLO、全场景比较、因子/机制对照及未决项索引。约定核验完成即可 `completed`，建议可为 adopt/revert/defer；可补采缺口返回 `needs_evidence`，执行错误保留已有产物。报告真实操作与失败，由主入口决定采纳、安排恢复和下一任务。
