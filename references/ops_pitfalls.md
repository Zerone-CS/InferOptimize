# 运维边界与版本化排障

本文件给检查方法，不把某次机器故障、错误码或耗时当作所有环境的规则。
具体命令先核对当前系统和权限；沿用用户已有授权，不为常规可逆工作重复申请。

## 1. 先确定目标归属

在服务启动前后记录主机、容器 ID、镜像、设备映射、端口、PID 与进程启动时刻。
进程可能改名为 `VLLM::EngineCore`/`VLLM::Worker_*`，只搜小写 vllm 或 python 可能漏查。
名称匹配只是线索；结合父子关系、容器归属、服务端点和设备使用确认目标。

停止顺序：

1. 正常停止当前实验管理的服务，等待约定退出时间。
2. 核实未退出 PID 仍是原进程，且属于目标实验，再发送正常终止信号。
3. 超时且确有必要时，对已核实的精确 PID 升级终止，不做全机名称模糊强杀。
4. 验证端口、目标进程和设备资源释放；保留失败与清理记录。

forkserver/resource_tracker 出现不等于持有设备内存。未知归属进程、其他容器设备映射
仅记录为共租/干扰线索，不自动停止或删除。驱动重启、芯片 reset、主机通信配置修改
超出普通实例调参；已有授权未覆盖时登记阻塞和所需动作，不擅自扩大范围。

## 2. 显存和设备共享

显存不足可能来自模型、KV、工作区、图捕获、运行库、其他进程、碎片或残留。
比较目标进程、框架可用内存、设备监控和启动分配日志；先确认各计数的含义和权限。
某次 npu-smi 读数异常不证明该工具在所有环境无效；框架查询也需确认设备索引和上下文。

容器设备共挂是否允许，取决于硬件、驱动、隔离模式与运行时配置。
先只读收集映射和完整错误栈，检查本环境支持条件，再决定是否需要隔离实验。
不能从“单卡正常、多卡失败”直接推出共挂、并行算法或网络配置中的某一个根因。

## 3. 版本与实际安装源

版本号之外，还要检查目标环境实际 import 路径、安装方式和生效库。
邻近 checkout 的代码与容器/site-packages 中执行代码可能不同。
源码安装记录 commit 与 dirty patch；wheel 安装记录版本、文件 hash 和可取得的构建来源。
检查时使用服务的 Python/环境；宿主机 import 正常不证明容器服务正常。

驱动/CANN/torch_npu/vLLM-Ascend 兼容性按当前发布说明、镜像和运行证据核对。
`ASCEND_VISIBLE_DEVICES`、设备手动绑定及 runtime 选项的行为随安装方式变化；
没有本环境的验证就不写通用禁令，也不为了复现旧经验替换用户已正常工作的部署方式。

多份 skill 副本分别记录实际加载路径与 hash。目录内容相同不代表存在同步机制。
更改源文件后需验证加载副本是否更新，不能只确认编辑器中的那一份。

## 4. 启动与退出

启动成功以目标端点就绪、worker 状态、模型加载和最小健康请求综合确认，
不只搜一句 startup complete。编译/图捕获耗时按本次日志记录，不固定为某分钟数。
失败保留第一处相关异常及上下文，检查 worker、调度器、运行时与 API 层的因果顺序；
API 的级联报错通常不是最早原因，但不能因此忽略 API 层自身故障。

共享内存广播超时可能与编译、卡住、worker 失败或资源问题相关。
观察后续进度、进程存活和日志关联，不能一概归为“无害”。
错误码仅作检索入口；匹配版本、算子、调用路径和完整报错后才决定处置。

## 5. profiling 入口检查

服务接口、profiler 配置形式、分析 API 和导出文件会随版本变化。
在当前 CLI 帮助、对应版本文档和运行源码中确认入口，再做最短有效采集验证。
不要把历史命令中的参数、API 导入位置或单 rank 分析耗时写成普适保证。

采集前确定要回答的问题、需要的 rank/host/device 字段、窗口及存储预算。
采集后检查文件大小、时间范围、实际 kernel/API/step 事件、事件丢失和 rank 覆盖。
API 进程的 trace 不自动拥有 worker 的设备事件；文件存在不等于关键字段存在。
CLI msprof、框架 profiler、服务层 profiler 的字段范围分别确认，不因共享底层能力而混同。

采集改变执行时序时，对照关闭重型采集的运行；既不能用污染数据计分，
也不能假定每个 kernel 的时长完全不受采集扰动。旧 trace 不补出未记录的业务状态。

## 6. 历史案例如何使用

旧方法来自一个 DeepSeek-V4-Flash-w8a8、8 die A3 场景的实验记录。
只在 raw manifest 能复原硬件、模型、版本、配置和负载时引用具体数值；
无法复原就标“历史线索，适用版本未验证”，不拿作当前测量或保证。

可保留为候选的线索包括：参数被平台覆盖、特定图形状回退、某通信路径需要额外配置、
某次设备共享导致初始化失败。每条案例应补齐 scope、观察、鉴别步骤和未排除解释，
不能把“曾经一起发生”写成充分条件。
